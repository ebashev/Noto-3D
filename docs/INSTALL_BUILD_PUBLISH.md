# Установка, сборка и публикация

Инструкция для подготовленного проекта **ebashev/Noto-3D**. Публикация в GitHub и публикация npm — два отдельных действия. Один `git push` не создаёт npm-пакет.

## 1. Инструменты

Установите Node.js 24 LTS с https://nodejs.org/ и Git с https://git-scm.com/downloads . npm поставляется с Node.js. Откройте терминал (Windows: PowerShell) и проверьте:

```sh
node --version
npm --version
git --version
```

Минимум: Node.js 22.14. Для описанной автоматической публикации требуется npm 11.5.1+. Проверенная сборка использует Node 24 и npm 11.9.0. Платные сервисы, свой сервер и GPU не нужны. Сначала распакуйте ZIP проекта; команды выполняются внутри папки с `package.json`.

## 2. Сборка готового комплекта

```sh
npm ci
npm run check
npm pack
```

`check` выполняет сборку, тесты Unicode/API, проверку типов и контрольных сумм **всех 11 964 изображений**. `npm pack` создаёт готовый `.tgz` и повторно проверяет комплект. Никакие файлы не публикуются этими командами.

В JS-компиляции нет TypeScript-транспиляции: исходный JS превращается в ESM/CJS-модули с каталогом. `.d.ts`/`.d.cts` поставляются отдельно. Сборка не скачивает заново изображения: они уже находятся в `img/`.

Для проверки без публикации в другом приложении:

```sh
npm install /absolute/path/to/emoji-datasource-noto3d-1.0.0.tgz
```

На Windows можно указать `C:/Users/YourName/Downloads/emoji-datasource-noto3d-1.0.0.tgz`.

## 3. Повторное изготовление изображений

Обычному пользователю пакета этот раздел не нужен. Если меняете размер/качество, нужны исходники 512 px.

### Из наших двух первоначальных ZIP

Распакуйте обе части в один каталог `Noto_3D_Emoji_512`. Импорт читает подпапки и проверяет SHA-256:

```sh
npm run import:originals -- "C:/path/to/Noto_3D_Emoji_512"
npm run images
npm run build
npm run check
```

### Из официального CDN

```sh
npm run fetch:originals
npm run images
npm run build
npm run check
```

Скачивание возобновляется: корректные файлы в `.cache/originals` пропускаются. Неудачные запросы повторяются до четырёх раз. Снимок фиксирован на 21.09.2026: если Google изменит URL `latest`, несовпадающие файлы отклоняются. Тогда используйте сохранённые ZIP, а для перехода на новый набор осознанно обновите CSV/метаданные и версию.

На Linux/macOS команды те же; меняется только путь. `sharp` обычно использует готовый бинарный модуль. Если на редкой платформе установка sharp не поддерживается, подготовленные изображения всё равно можно использовать; регенерацию делайте на поддерживаемом Node.js/ОС.

## 4. Загрузка в уже созданный GitHub-репозиторий

Репозиторий найден по адресу https://github.com/ebashev/Noto-3D . Ничего вручную создавать заново не требуется.

Из папки распакованного проекта:

```sh
git clone https://github.com/ebashev/Noto-3D.git ../Noto-3D-repo
node scripts/copy-to-repo.mjs ../Noto-3D-repo
cd ../Noto-3D-repo
npm ci
npm run check
git add .
git commit -m "Add Noto 3D emoji package"
git branch -M main
git push -u origin main
```

Скрипт копирования не переносит `.git`, `node_modules`, временные оригиналы и архивы. Если в целевом репозитории уже появился файл с другим содержимым, скрипт остановится **до копирования** и покажет конфликт: сравните изменения и объедините их вручную. Не применяйте `--force` к push.

Git может запросить вход в GitHub через браузер/credential manager. Пароль учётной записи не вставляют вместо токена. Для пустого репозитория можно также скопировать содержимое проекта через файловый менеджер, сохранив `.github`, `.gitignore` и `.gitattributes`.

Изображения находятся непосредственно в Git, без Git LFS, чтобы их можно было раздавать через GitHub CDN. Крупные исходники 512 px и ZIP не коммитятся. Первоначальные оригиналы уже доступны в двух отдельных архивах из переписки.

## 5. Первая публикация npm

До публичного распространения прочитайте `LICENSE.md`: графика не становится MIT только потому, что код проекта использует MIT. У Google сохранены противоречащие друг другу лицензионные указания; для публичного релиза уточните применимую лицензию статических 3D PNG у правообладателя и обновите раздел графики в LICENSE/NOTICE. Скрипты не публикуют ничего автоматически при установке или сборке.

Создайте/используйте свою учётную запись на https://www.npmjs.com/ . Имя GitHub и имя npm могут отличаться.

```sh
npm login
npm whoami
npm view emoji-datasource-noto3d name
```

Ответ `E404` на последнюю команду означает, что пакет с таким именем не найден сейчас; это не резервирует имя. Если имя занято чужим пакетом, используйте собственный npm scope. **Подставьте результат `npm whoami` вместо `YOUR_NPM_USER`:**

```sh
npm run configure -- @YOUR_NPM_USER/emoji-datasource-noto3d
npm run check
npm pack --dry-run
npm publish --access public
```

В реальной команде имя должно быть строчным; `YOUR_NPM_USER` — обозначение для замены. Можно сохранить исходное `emoji-datasource-noto3d`, если оно доступно и не нужен scope: тогда команду configure пропустите.

`configure` меняет имя в package.json и lockfile; `build` обновляет имя в JS API и manifest. README содержит примеры с исходным именем: замените его в инструкции для своих пользователей. При публикации npm может потребовать подтверждение входа/2FA. Секреты и `.npmrc` с токенами не добавляются в Git.

Если меняли имя пакета, сохраните изменения в Git **до создания тега релиза**, чтобы GitHub Actions позже публиковал то же имя:

```sh
git add package.json package-lock.json dist manifest.json README.md
git commit -m "Configure npm package name"
git push origin main
```

После успешной публикации:

```sh
npm view YOUR_ACTUAL_PACKAGE_NAME@1.0.0 name version dist.unpackedSize
```

Версия npm неизменяема: исправления публикуйте как новую версию. Перед первой публикацией убедитесь, что поле repository соответствует `ebashev/Noto-3D`; оно уже настроено.

## 6. CDN-ссылки после публикации

Для исходного имени:

```text
https://cdn.jsdelivr.net/npm/emoji-datasource-noto3d@1.0.0/img/noto3d/webp/128/1f920.webp
https://unpkg.com/emoji-datasource-noto3d@1.0.0/img/noto3d/png/64/1f920.png
```

Для scope путь содержит `@username/имя-пакета@версия`. `getEmojiUrl()` формирует правильный URL из имени внутри package.json.

До npm-публикации можно использовать репозиторий после push и создания тега:

```sh
git tag v1.0.0
git push origin v1.0.0
```

```text
https://cdn.jsdelivr.net/gh/ebashev/Noto-3D@v1.0.0/img/noto3d/webp/128/1f920.webp
```

Не пользуйтесь `@latest`/`@main` для производственного приложения. Открывайте реальную PNG/WebP ссылку и проверяйте HTTP 200 после публикации. Документация здесь приводит будущие URL, не заявляет, что они уже доступны.

По документации jsDelivr от 23.09.2026 стандартный предел пакета — 150 MB; для GitHub отдельный файл не должен превышать 20 MB. В проекте более строгий бюджет 120 MB для npm-содержимого. Фактический размер и контрольные суммы проверяет `npm run verify`. CDN — внешний сервис; закладывайте fallback и возможность собственного хостинга.

## 7. Обновления

После изменений выполните:

```sh
npm run check
git add .
git commit -m "Update Noto 3D package"
npm version patch
git push origin main --follow-tags
npm publish --access public
```

Скрипт `version` пересобирает файлы с новым номером и включает их в коммит версии. Не смешивайте ручную публикацию с автоматической для одного тега.

## 8. GitHub Actions

В `.github/workflows/ci.yml` настроены проверки push/PR. `.github/workflows/publish.yml` запускается **вручную** из Actions: выберите tag `v1.0.1` и нажмите Run workflow.

Для публикации через OIDC сначала опубликуйте первый пакет вручную. Затем в npm → package → Settings → Trusted Publisher настройте GitHub Actions:

- Organization/user: `ebashev`
- Repository: `Noto-3D`
- Workflow filename: `publish.yml`
- Environment: оставьте пустым, если не добавляли environment в workflow.

Разрешите этому publisher непосредственный `npm publish`, если в текущем интерфейсе npm есть выбор Allowed actions. Workflow использует `id-token: write`, Node 24 и npm 11.9.0; постоянный NPM_TOKEN не нужен. Источник: https://docs.npmjs.com/trusted-publishers/ .

Workflow проверяет соответствие тега версии и повторно запускает проверки. Не включайте автоматическую публикацию до настройки своего npm-пакета и завершения лицензионного вопроса.

## 9. Почему не один пакет на 572 МБ

Количество файлов не означает, что браузер загрузит их все. Но полный оригинальный архив увеличивает npm install, репозиторий и размер CDN-пакета. Поэтому в релиз входят реальные производные 64/128/256 px, а большие PNG остаются исходным материалом. При необходимости оригинала API `getGoogleUrl()` возвращает официальный URL Google; такой URL зависит от Google и `latest`, а не от версии нашего пакета.
